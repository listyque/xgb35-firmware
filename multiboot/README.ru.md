# Установщик мультибута XGB35 · предварительная версия

[EN](README.md) · **RU**

[Релиз установщика](https://github.com/listyque/xgb35-firmware/releases/tag/multiboot-installer-v0.1.0)

Утилита для Windows готовит **отдельную microSD** для XGB35 из локальных файлов сборки. Она помещает загрузочный образ Actions BootROM перед первым разделом и устанавливает на этот раздел файловую систему Alpine и образы штатной системы для 480×320. Среду выполнения и графическое меню предоставляет локальная загрузочная сборка XGB35.

## Требования

- Windows, Python 3.11 или новее и установленный WinUSB-драйвер для ADB-устройства XGB35 `10d6:fe02`.
- Работающая загрузка XGB35 из RAM с ADB и `/bin/xgbshell`.
- Запасная microSD в приставке. Установка заменяет MBR и форматирует карту.
- Локальные файлы сборки XGB35 по схеме ниже. Архив установщика содержит утилиты для ПК. Загрузочный образ с CFW XGB35, Alpine и образы штатной системы берутся из локальной сборки.

```text
build-artifacts/
  sd-boot-autonomous/
    manifest.json
    sd-boot-lba1.bin
  alpine-bundle/
    manifest.json
    alpine-xgb35-rootfs.tar.gz
  update.zip_DATA/
    3.system.img
    5.res.img
```

Для SYSTEM и RES нужны **образы штатной системы для 480×320**, которые использует среда XGB35. В штатном пакете восстановления от августа 2023 года другой профиль экрана. Установщик сверяет ожидаемые SHA-256 обоих файлов до подключения к приставке.

## Проверка и установка

В папке с распакованным установщиком проверьте входные файлы без обращения к USB:

```powershell
python install_sd.py --inputs 'D:\path\to\build-artifacts'
```

Когда XGB35 загрузится из RAM и вы вставите запасную карту, запустите установку с явным указанием на стирание карты:

```powershell
python install_sd.py --inputs 'D:\path\to\build-artifacts' --erase-sd
```

Установщик проверяет, что Linux определяет `/dev/mmcblk0` как SD-карту, записывает загрузочные секторы и монтирует новый раздел 1, начинающийся с LBA 32768. Затем он устанавливает `/linux/alpine.ext4`, `/linux/stock-system.img` и `/linux/stock-res.img`, сверяет загрузочную область и штатные образы обратным чтением и размонтирует раздел. Целевое устройство установщика — microSD.

**Статус проверки.** Валидация входных файлов и самотест протокола ADB прошли в Windows. Установку и самостоятельный холодный старт ещё предстоит проверить на приставке. Отдельная CFW дорабатывается.

## Проверка PowerVR SGX

В новой загрузочной сборке CFW команда `/bin/sgx-init` запускает PowerVR Services на ядре Actions 3.10.52. Она монтирует `/mnt/sd/linux/stock-system.img` только для чтения и запускает штатный `pvrsrvctl` с библиотеками uClibc из того же образа. Для уже загруженной CFW выполните из каталога `multiboot`:

```powershell
python adb_winusb.py push sgx-init.sh /tmp/sgx-init.sh
python adb_winusb.py shell '/bin/busybox sh /tmp/sgx-init.sh'
python adb_winusb.py shell 'cat /proc/pvr/version; dmesg | grep -i "DDK"'
```

На XGB35 при 900 МГц появились `/dev/pvrsrvkm` и запись о совпадении версий DDK `1.14@4004414`. Драйвер сообщил ревизию `130`. Скрипт запускается вручную и использует текущую частоту CPU.

Штатному DDK 1.14 нужны совместимые ARMv7 EGL/GLES и оконный слой. В проверенных образах SYSTEM и RES такого комплекта нет. После запуска штатных PowerVR Services `glxinfo -B` в Alpine Desktop показал `llvmpipe` и `Accelerated: no`. Для теста на GPU используется отдельный стек DDK 1.8, описанный ниже.

- В SYSTEM прошивки Powkiddy X70 от 2022-11-23 тот же DDK `4004414`. `pvrsrvctl`, `libsrv_init.so`, `libsrv_um.so` и `libpvr2d.so` побайтово совпадают с XGB35. В SYSTEM и RES нет EGL, GLES и WSEGL. [Архив прошивок X70](https://fox-exe.ru/Files/PowKiddy_x70/)
- Модуль LeMaker Guitar собран для `3.10.37` с DDK `MAIN@3625561`. Руководство платы указывает GPU SGX544MP. [Модуль LeMaker](https://github.com/elar-systems/LeMaker-Guitar/blob/master/hwpack/rootfs/lib/modules/3.10.37/kernel/drivers/gpu/pvr/eurasia_km/pvrsrvkm.ko) · [Руководство](https://mirror.lemaker.org/LeMaker_Guitar%E7%94%A8%E6%88%B7%E6%89%8B%E5%86%8CV1.0.pdf)
- Комплект CI20 для SGX540 rev. 130 использует MIPS и DDK `1.14.3841212`. Исследовательский код CI20 открывает устройство DRM и создаёт контекст памяти, а тест рисования вызывает проприетарный GL. [Версии DDK](https://github.com/openpvrsgx-devgroup/linux_openpvrsgx/wiki/DDK-versions) · [Исходники CI20](https://github.com/Hazematman/sgx540-reversing)
- Исходники LeMaker Linux Actions `3.10.y` содержат платформенный код OWL в DDK `1.12@2701748`. В конфигурации `gs702c` указаны SGX540 rev. 130 и `SUPPORT_SLC`. Этот код служит ориентиром для порта. В штатном модуле XGB35 управление ресурсами идёт через платформенное устройство, runtime PM и таблицу OPP из DTB. [Платформенный код OWL](https://github.com/LeMaker/linux-actions/tree/linux-3.10.y/drivers/gpu/drm/gpu/eurasia_km/services4/system/owl) · [Конфигурация сборки](https://github.com/LeMaker/linux-actions/blob/linux-3.10.y/drivers/gpu/drm/gpu/eurasia_km/eurasiacon/build/linux2/owl_android/Makefile)

Из архива DDK `1.8@869593` собран прототип EGL, GLES2, компилятора GLSL и Services для ARMv7 Cortex-A5, SGX540 rev. 130 и glibc. В QEMU загрузились `libEGL.so`, `libGLESv2.so` и `libglslcompiler_SGX540_130.so`, `pvrsrvctl --help` отработал. Штатный модуль `1.14@4004414` использует другой интерфейс. Пакет для Alpine собран с musl. [Архив исходников DDK](https://github.com/aosp/gfx_linux_ddk)

В штатном DTB узел `actions,ats3605-gpu` задаёт регистры `0xb0350000` размером `0x10000`, прерывание GIC SPI 4, четыре тактовых входа `gpu`, `gpu_core`, `gpu_mem`, `gpu_sys`, сброс `gpu` и домен питания. Заданные частоты GPU составляют 218, 327 и 436 МГц. Проверка на 900 МГц относится к частоте CPU. Ревизию `130` сообщил драйвер, идентификатор GPU напрямую не прочитан.

Патч DDK 1.8 подключает модуль к ATS3605 через device tree и управляет питанием, тактированием и прерываниями GPU. Пробная сборка на исходниках Linux 3.10.52 повторилась из оригинального архива. У модуля и штатного драйвера совпали `vermagic`, размер `struct module` и смещения `init`/`exit`. Все 140 импортов диагностической сборки найдены среди штатных экспортов. Конфигурация исходников ядра взята от VExpress. [Скрипт сборки](../drivers/sgx540/build-reference.sh) · [Патч](../drivers/sgx540/ddk18-ats3605.patch)

Тест создаёт поверхность EGL pbuffer, рисует зелёный треугольник на чёрном фоне и проверяет цвет в центре и в углу. Без аргументов размер кадра 32×32. Команда `gles2-probe triangle.ppm` рисует кадр 256×256 и сохраняет пиксели из `glReadPixels` для просмотра. В QEMU прошёл самотест конфигурации WSEGL. [Тест GLES2](../drivers/sgx540/gles2-probe.c)

После запуска `pvrsrvctl --dump-debug --force-regs` на проверяемой XGB35 команды ADB перестали отвечать. Для проверки версии подходит чтение `/proc/pvr/version`.

В Desktop Mode на XGB35 при 900 МГц `es2_info` показал `GL_RENDERER: llvmpipe` и `OpenGL ES 3.2 Mesa 23.3.6`. Модуль DDK 1.8 загрузился из RAM, привязался к GPU и создал `/dev/pvrsrvkm`. При запуске Services микрокод не выставил бит готовности, `PVRSRVInitSrvDisconnect` вернул `24` (`PVRSRV_ERROR_RETRY`), и тест рисования не запустился. После первой попытки перестал отвечать ADB. Диагностическая сборка отключила тактирование и питание GPU при ошибке. После повторного теста проверены доступность ADB, отсутствие тестового модуля и работа Xorg.

После включения системного кэша SGX, который штатный драйвер настраивает через `MNE_CR_CTRL`, `pvrsrvctl --start --no-module` прошёл. Нативный порт пропускает Android-настройку `/sys/egl/egl.cfg`, которая мешала повторной загрузке в той же сессии.

Тест задаёт `ParamBufferSize=262144` и `MaxParamBufferSize=262144` в локальном `powervr.ini`. Для выделения страниц модуль вызывает экспортируемый аллокатор ядра, поскольку смещение `node_zonelists` в штатном ядре (`0xb40`) отличается от VExpress (`0x600`). При автоматическом отключении GPU между заданиями наблюдались тайм-ауты повторного запуска микрокода и `WaitForRender`.

С отключённым автоматическим переходом GPU в сон тест дважды прошёл после отдельных загрузок модуля в RAM. На XGB35 в Desktop Mode при CPU 900 МГц драйвер сообщил `PowerVR SGX 540` и кэшированную частоту GPU 120 МГц. Прошивка программирует DEVPLL в обход учёта частот Linux. Центр был зелёным `(0,255,0)`, угол чёрным `(0,0,0)`, `glGetError` вернул ноль. Третий запуск сохранил кадр 256×256 с теми же контрольными цветами. Штатные приложения Alpine продолжают использовать Mesa.

Кадр открыли в штатном `imlib2_view` на дисплее `:0`. Снимок этого окна через `imlib2_grab -id` совпал с выводом `glReadPixels` по всем 65 536 пикселям. Внутри треугольника оказалось 20 808 зелёных пикселей. Для такого показа достаточно скопировать готовый кадр в X11.

### Бенчмарк GLES2 на XGB35

Один исходник рисует 15 вращающихся кубов с перспективой, освещением, шахматным узором и проверкой глубины. Каждый кадр содержит 180 треугольников. Оба рендерера используют pbuffer 480×320, формат RGBA8, глубину 24 бита и трафарет 8 бит, без MSAA. После секунды прогрева программа три раза рисует сцену по пять секунд. Синхронное чтение одного пикселя завершает каждый кадр. Показ в X11 и запись снимка выполняются вне замера. [Исходник бенчмарка](../drivers/sgx540/gles2-cubes.c)

| Рендерер при CPU 900 МГц | Кадры в трёх прогонах | Медиана FPS |
|---|---|---:|
| PowerVR SGX540, унаследованная частота GPU (без проверки регистра) | 1547 / 1545 / 1547 | 309,2 |
| Штатный Mesa llvmpipe | 76 / 76 / 75 | 15,1 |

Отношение медиан на этой сцене составило 20,5. Для запуска укажите ожидаемый рендерер первым аргументом, путь для контрольного кадра PPM можно передать вторым. В Alpine Desktop тест запускается с `EGL_PLATFORM=surfaceless`, чтобы использовать RGBA8. При одном запуске PowerVR микрокод вернул ошибку до начала замера. Повторная загрузка модуля прошла без перезагрузки приставки.

### Драйвер для Alpine Desktop

Пакет содержит согласованные модуль ядра 3.10.52, Services, компилятор шейдеров и библиотеки EGL/GLES2 для musl. Для сборки нужны исходные архивы и входные файлы с контрольными суммами из скриптов. Скрипт ядра использует отдельное окружение Ubuntu с рабочим каталогом в /opt. Для пользовательской части нужны ARM hard-float cross-компилятор, 32-битный компилятор C/C++ для хоста и qemu-arm. В переменной DRIVER укажите абсолютный путь к каталогу drivers/sgx540. [Сборка ядра](../drivers/sgx540/build-reference.sh) · [Сборка для Alpine](../drivers/sgx540/build-musl.sh)

```sh
sh "$DRIVER/build-reference.sh"
sh "$DRIVER/build-musl.sh"
python3 "$DRIVER/package-driver.py" pvrsrvkm_sgx540_130-reference.ko ddk18/um-musl/target xgb35-sgx540-alpine.tar.gz
```

Скопируйте архив и install-driver.sh в файловую систему Desktop. Команды установки выполняются от root внутри Alpine Desktop. Каждое приложение может выбрать SGX через sgx-run. Драйвер поддерживает поверхности EGL pbuffer. OpenGorky совмещает полученную картинку меню со своим кадровым буфером RGB565. [Установщик](../drivers/sgx540/install-driver.sh)

```sh
sh install-driver.sh xgb35-sgx540-alpine.tar.gz
sgx-run --init
sgx-run ./cubes 'PowerVR SGX 540'
sgx-run --stop
```

Штатный профиль пакета выставляет три такта GPU на 360 МГц делителями от DDRPLL 720 МГц. Профиль для замера 120 МГц использует тот же источник. Частотой CPU управляет ОС. На сцене с кубами 480×320 медианы трёх пятисекундных прогонов составили 167,5 FPS при CPU/GPU 900/120 МГц и 264,3 FPS при 1200/360 МГц. Прочитанные регистры GPU равны 0xFE360036 и 0xFA320032. При запросе 400 МГц исходное дерево тактирования вернуло ошибку. Для прежнего замера 309,2 FPS регистры делителя не записывались.

#### Прямой вывод в fbdev

`sgx-run --fbdev PROGRAM [ARGS...]` выбирает отдельный WSEGL для EGL-окон. После `eglGetDisplay(EGL_DEFAULT_DISPLAY)` приложение запрашивает `EGL_WINDOW_BIT` и RGB565. В `eglCreateWindowSurface` передаётся `(EGLNativeWindowType)(uintptr_t)1` для `/dev/fb0` или `2` для `/dev/fb1`. Размер берётся из framebuffer. Для LCD XGB35 это 320×480 в нативной ориентации.

WSEGL импортирует область framebuffer в адресное пространство SGX через Services. `eglSwapBuffers` завершает рендер в заднюю страницу, затем WSEGL вызывает `FBIOPAN_DISPLAY` с `FB_ACTIVATE_VBL`. Приложению нужен исключительный доступ к выводу, поскольку Xorg и fbdev могут писать в один framebuffer. Поддерживаются режимы RGB565 с двумя полными страницами и аппаратным панорамированием. [WSEGL](../drivers/sgx540/wsegl-fbdev.c) · [Проверка GLES2](../drivers/sgx540/gles2-fbdev-probe.c)

На XGB35 проверены по пять смен страниц на `fb0` (320×480) и `fb1` (1920×1080). Тест прочитал контрольные точки из framebuffer после смены страницы и сверил исходное смещение при закрытии EGL. Вызовов `glReadPixels` в этом пути нет.
