# Диагностический Linux для ATM7051H

Экспериментальный набор для пробной загрузки в RAM. Это **не оригинальная прошивка**, не `update.zip` и не физический образ NAND. Он не восстанавливает загрузчик сам по себе. На приставке не проверен.

## Что подготовлено

- `uImage`: неизменённое ядро Linux 3.10.52 из предоставленного `E:\update.zip`.
- `kernel.dtb`: неизменённое описание оборудования из того же обновления.
- `ramdisk.img`: новый initramfs в legacy uImage с gzip, статической ARM BusyBox 1.14.3, диагностикой и интерактивной консолью.
- `manifest.json`: происхождение, контрольные суммы и выполненные проверки.

Код `/init` монтирует только proc, sysfs, devtmpfs и devpts, выводит диагностику и открывает shell. Он не загружает NAND-модули, не монтирует разделы приставки и не запускает штатные программы обновления. NAND-модули и обновлятор в новый initramfs не включены. Это ограничение нашего userspace: поведение встроенных драйверов чужого ядра на этой плате аппаратно не проверено.

Ядро и BusyBox старые; этот набор предназначен для локальной диагностики, без сетевых сервисов. Графического меню, эмуляторов и поддержки всех кнопок в нём нет.

## Совместимость ещё не установлена

Плата пользователя: `LLW7051-057-MAIN-BOARD V2.0`, дата `2022-07-19`. Метка конфигурации в обновлении: `057V1_vLCD0_V1.0`. Совпадение номера 057 не доказывает совместимость ревизии, LCD, питания или памяти. Именно после этого обновления приставка перестала загружаться; ядро и DTB взяты из него как диагностические кандидаты, а не как заведомо исправная заводская прошивка.

DTB задаёт `console=ttyS5,115200`; UART5 включён. У SD-контроллера есть `sdio_uart_supported`. Карта должна быть вынута при использовании её контактов для UART. Поле `/memory/reg` в исходном DTB заполнено нулями: перед запуском ядра загрузчик должен задать действительный диапазон RAM. Самостоятельный запуск этого DTB без соответствующих исправлений загрузчика не проверен.

## Что нужно до запуска

1. Снять UART-лог включения при 115200, 8N1, без управления потоком. Сначала достаточно направления приставка → ПК. Для Uno R3/ATmega328P с удерживаемым RESET основного контроллера на GND вход USB-моста находится на **D1/TX**. GND объединяется. Питание приставки остаётся собственным.
2. Для команд и передачи файлов понадобится второе направление с подходящими логическими уровнями. **D0/RX такой Uno является выходом USB-моста с уровнем около 5 В; напрямую к RX процессора его не подключать.** Пины 5V, 3.3V и VIN Uno к приставке не подключаются. Точная модель USB-моста и уровни входа ещё не проверены.
3. Если удастся попасть в U-Boot, сохранить вывод команд `version`, `help`, `bdinfo`, `printenv`, `help loady`, `help bootm`. Они нужны для выбора свободных RAM-адресов и способа загрузки. Не выполнять `saveenv`, стирание или запись NAND.
4. В исследованном файле `uboot.bin` есть строки команд `loady` (YMODEM), `loadb` (Kermit), `bootm` и `ramboot`. Это признак возможной загрузки по UART, но не доказательство, что именно такой загрузчик сейчас работает на устройстве.

После проверки лога можно выбрать адреса без пересечения с U-Boot, распаковываемым ядром, initramfs, DTB и зарезервированной памятью; затем передать три файла и выполнить загрузку в RAM. Готовой команды с угаданными адресами здесь нет. Параметры загрузки должны включать UART-консоль и `rdinit=/init`, без `noinitrd` и принудительного запуска штатной системы из NAND.

**Не переименовывать этот ZIP в `update.zip`, не записывать его через программатор и не запускать штатное обновление этими файлами.** Если приставка не доходит до работающего загрузчика, наличие диагностического Linux само по себе её не оживит: сначала нужен доступный способ восстановления загрузчика, например подтверждённый ADFU.

## После успешной загрузки

На UART появятся баннер `ATM7051H diagnostic Linux` и приглашение `diagnostic#`. Команда `diagnose` повторно выводит сведения о CPU, памяти, параметрах загрузки, монтированиях, модулях, разделах и последние сообщения ядра. Сохранить весь лог. Отсутствие изображения на LCD не исключает успешной работы консоли.

## Воспроизведение сборки

В исходном рабочем каталоге выполнить `python firmware/prepare_diagnostic.py`. Нужен только Python со стандартной библиотекой и уже извлечённые `build/firmware-inspection/misc/{uImage,kernel.dtb,ramdisk.img}` с указанными в скрипте SHA256. Скрипт берёт только BusyBox из исходного ramdisk, создаёт новый CPIO и uImage, проверяет форматы и выпускает этот набор и ZIP рядом со скриптом. Исходные файлы не изменяются; пересборки самого ядра здесь нет.

Проверки на ПК: SHA256 исходников, CRC32 заголовка и данных uImage, ARM ELF без динамического загрузчика, gzip/CPIO, права и владельцы файлов, номера устройств, отклонение повреждённых и небезопасных входных данных, целостность ZIP. Это не заменяет загрузку на устройстве.
