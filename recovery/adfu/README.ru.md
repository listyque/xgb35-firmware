# Восстановление XGB35 из «кирпича» через USB ADFU

[English](README.md)

Набор подготовлен для **LLW7051-057-MAIN-BOARD V2.0 от 2022-07-19** с Micron **MT29F64G08CBABA WP:B**, ID `2c 64 44 4b a9`. Страница NAND содержит 8192 байта данных и 744 байта OOB. Сверь ревизию, маркировку чипа и расположение площадок. [Плата](../../docs/hardware.ru.md) · [Фото ADFU](../../photos/adfu-close.png)

1. Выключи приставку, вынь microSD и подключи USB-кабель с линиями данных. Сначала попробуй Reset без перемычки. На проверенной приставке BootROM мог сам войти в ADFU, если не находил загрузочный сектор. Если это не сработало, замкни подтверждённую пару площадок ADFU на время Reset и сними перемычку после появления `USB\VID_10D6&PID_10D6`. У ADB в работающем Linux другой USB ID.
2. Открой PowerShell в папке этого README. Если драйвер WinUSB ещё не установлен, выполни первую команду от имени администратора. Во второй команде найди интерфейс с `VID_10D6&PID_10D6` и скопируй его полный путь, начиная с `\\?\USB#`.

   ```powershell
   pnputil /add-driver .\adfu-driver\adfuwinusb.inf /install
   pnputil /enum-interfaces /enabled /class '{FF7B846F-B0A3-45C0-B0FC-D8122086996D}'
   $env:ACTIONS_ADFU_PNP_PATH = Read-Host 'Полный путь интерфейса ADFU'
   ```

3. Считай физические блоки 0 и 1 вместе с OOB. Скрипт сохраняет файл на ПК. До повторного чтения сохрани отдельно первую копию и сравни SHA-256. Ожидаемый размер — **4 575 232 байта**. Чтобы прочитать первые 32 МиБ данных с OOB, запусти команду без `--pages`.

   ```powershell
   python -B adfu_read_nand.py $env:ACTIONS_ADFU_PNP_PATH --pages 0 512
   Get-FileHash -Algorithm SHA256 .\adfu-nand-pages-0-512-raw-with-oob.bin
   ```

4. Первые две команды проверяют файлы на ПК. Третья запускает диагностический сервис из RAM. Четвёртая сохраняет текущее содержимое блока 0 и показывает хэши целей.

   ```powershell
   python -B adfu_autonomous_service.py --dry-run --diagnostic
   python -B adfu_write_nand_block0.py plan
   python -B adfu_autonomous_service.py --diagnostic
   python -B adfu_write_nand_block0.py inspect
   ```

5. Если плата и NAND совпадают и требуется восстановить блок 0 из опубликованного проверенного образа, подставь два хэша, которые вывела команда `inspect`. `rollback` стирает и программирует физический блок 0 с OOB и проверяет его обратным чтением. Блок 1 сохраняется. Режим `write` выбирает экспериментальный образ.

   ```powershell
   python -B adfu_write_nand_block0.py rollback --expect-current '<current_block0_sha256>' --execute-block0 '<target_hashes.rollback>'
   ```

   Дождись записи `complete` перед Reset. Если операция прервалась, сохрани её журнал и исходный снимок. Зайди в ADFU и выполни `inspect` для текущего состояния. На тестовом экземпляре сырое чтение разошлось на странице 4. Восстановление завершилось после возобновлений с проверкой декодированных данных аппаратным ECC. `python -B adfu_resume_block0.py --start-row 5` проверяет известный частично записанный шаблон без программирования. Скрипт поддерживает также точки 9 и 12 для этого случая и отказывается продолжать, если последующие страницы уже содержат данные. Параметр `--continue-block0` разрешает запись и требует точного SHA-256 образа восстановления.

[Архив восстановления и SHA-256](nand-write-preparation/) · [Разбор BootROM](atm7051h-bootrom-nand.md) · [Штатное обновление PATO](../../firmware/stock/README.ru.md)

План и обе версии сервиса RAM можно проверить на ПК. Архив блока 0 снят с проверенного экземпляра. Другой NAND или повреждение запасного блока требуют отдельной диагностики.
